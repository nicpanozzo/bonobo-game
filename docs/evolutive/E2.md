# E2 · Versioni e rilasci leggeri: numero visibile, note automatiche, avviso

Issue: #106 · ondata 1 · [piano](../piano-prodotto.md)

**Obiettivo:** il giocatore vede che versione ha, sa cosa è cambiato e viene avvisato quando deve aggiornare, invece di ritrovarsi con un'app che non entra più nelle stanze.
**Perché serve a un prodotto professionale:** oggi ogni merge che tocca `godot/` o il server pubblica una Release `app-<numero>` (`.github/workflows/app.yml`) con note sempre uguali; `package.json` dice `0.1.0`, `godot/export_presets.cfg` dice `0.1` e il gioco non mostra niente. Un'app vecchia contro un server nuovo si rompe in silenzio.

## Passi

### Passo 1: una versione sola, mostrata nel gioco
- Fonte unica: `version` in `package.json` (semver, si parte da `0.2.0`). Nuova costante `PROTOCOL_VERSION = 1` in `src/shared/constants.ts`: sale solo quando cambia `types.ts` in modo incompatibile.
- `scripts/export-godot.ts` scrive `version` e `protocol` in `godot/data/game.json` (la CI controlla già che sia allineato).
- `.github/workflows/app.yml`: prima dell'esportazione copia la versione in `application/short_version` e `application/version` di `godot/export_presets.cfg` (solo nel runner, non si committa).
- Godot: versione in piccolo nel piede della lobby (`lobby.gd`, accanto a "Crediti") e nel menu Esc (`pause_menu.gd`), letta da `game.json`.
- **Fatto quando:** cambiando `version` in `package.json` e rilanciando `npm run export:godot`, la lobby Godot mostra il numero nuovo; la CI fallisce se `game.json` non è stato rigenerato.

### Passo 2 (Protocollo): avviso, non blocco, se l'app è vecchia
- PR con titolo `Protocollo: versione del client nel join e rifiuto con motivo`. In `types.ts`: `join` riceve `version?: string` e `protocol?: number`; `welcome` porta `serverVersion`; nuovo evento server `refused: { reason: "outdated" | "full" | "limit"; message: string }` (unico evento di rifiuto, lo usa anche E4).
- Fase precoce: il server **non blocca** chi ha una versione diversa; blocca con `refused("outdated")` solo se `protocol` è diverso da `PROTOCOL_VERSION`. Chi non manda niente (app vecchie) entra comunque.
- Godot: con versione diversa mostra un banner "C'è una versione nuova" con il link al download; con `refused` mostra il messaggio invece di "Connessione persa".
- **Fatto quando:** `npm test` copre i casi in `src/server/version.ts`; un client Godot con versione vecchia gioca e vede il banner, uno con `protocol` cambiato a mano vede il messaggio e non entra.

### Passo 3: note di rilascio automatiche su Discord
- Le Release `app-N` che `app.yml` pubblica a ogni merge restano il modo di distribuire: niente tag a mano.
- Le note di ogni Release elencano i titoli delle PR dall'ultima (`--generate-notes`, categorie per etichetta in `.github/release.yml`), con il paragrafo di installazione di oggi in testa.
- `scripts/discord.mjs`: comando `release` che posta titolo, novità e link; lo lancia `app.yml` a Release pubblicata.
- **Fatto quando:** un merge che tocca `godot/` produce una Release con le novità scritte e un messaggio sul Discord, senza scrivere niente a mano.

## Rischi e decisioni aperte
- **Rilasci:** in questa fase ogni merge è un rilascio (le Release `app-N`); la versione in `package.json` sale a mano quando il gruppo lo decide, non a ogni merge.
- Le app già scaricate non mandano la versione: entrano comunque, così nessuno resta fuori.
- Il passo 2 tocca `join` e `welcome` come E5 (token di riconnessione): due PR di protocollo vanno fatte una dopo l'altra, non insieme.
- Chi sale di versione: proposta, `minor` per funzioni nuove, `patch` per correzioni, `major` resta 0 fino al pubblico (E20).

## Per gli agenti
- **Stato:** pronto (passi 1 e 3); passo 2 dopo il passo 1.
- **Corsia:** Rilasci.
- **File suoi:** `package.json` (solo `version`), `.github/workflows/app.yml`, `.github/release.yml`, `scripts/export-godot.ts` (solo i campi di versione), `scripts/discord.mjs` (comando `release`), `src/server/version.ts`; in Godot solo le righe della versione in `lobby.gd`, `pause_menu.gd`, `main.gd`, `settings.gd`.
- **Non toccare:** `src/shared/physics/`, `godot/data/` a mano, `src/client/`.
- **Dipende da:** niente. Passo 2 da coordinare con E4 ed E5 su `index.ts` e `types.ts` (prima E2, che è piccola, poi E5).
- **Come provarlo:** `npm run typecheck && npm test && npm run build && npm run export:godot`; `godot --headless --path godot --quit-after 60` senza `SCRIPT ERROR`; due istanze Godot con `npm run dev` (una con protocollo giusto entra, una con versione vecchia vede il banner, una con protocollo cambiato vede il rifiuto); il passo 3 si vede al primo merge dopo la PR.
